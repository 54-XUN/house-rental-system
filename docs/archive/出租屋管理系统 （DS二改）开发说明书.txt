# 房屋出租管理系统 — 开发规格说明书

## 一、项目概述
- 单机桌面应用，双击 .exe 运行，无需浏览器和 Python 环境。
- 技术栈：PyWebView + Flask (后端) + Vue 3 + Element Plus (前端) + SQLite。
- 单人使用，无登录。

## 二、数据库设计 (SQLite)

### 2.1 房源表 houses
字段：id(INT PK), house_code(TEXT UNIQUE), add_date(TEXT), community(TEXT), address(TEXT), floor(INT), room(INT), hall(INT), area(REAL), rent(REAL), tags(TEXT), contract_code(TEXT), expire_date(TEXT), status(TEXT)
说明：tags 用逗号分隔；status 为 空闲/已租/即将到期，根据 expire_date 和当前日期自动计算。

### 2.2 客户表 customers
字段：id(INT PK), customer_code(TEXT UNIQUE), add_date(TEXT), name(TEXT), id_card(TEXT), phone(TEXT), wechat(TEXT), tags(TEXT), status(TEXT)
说明：tags 与房源 tags 共用同一套选项；status 为 跟进中/已签单/已放弃。

### 2.3 合同表 contracts
字段：id(INT PK), contract_code(TEXT UNIQUE), sign_date(TEXT), house_code(TEXT), customer_code(TEXT), months(INT), start_date(TEXT), end_date(TEXT), deposit(REAL, 可为空), monthly_rent(REAL), total_amount(REAL)
业务逻辑：total_amount = months * monthly_rent + deposit (deposit 空则 0)；创建合同时自动更新房源表 contract_code、expire_date、status 为“已租”；删除合同时清空房源表对应字段并改状态为“空闲”。

### 2.4 参数设置表 settings (key-value)
默认键值：
- card_columns = "7"
- vacant_style = "WPS"
- rented_style = "WPS"
- expiring_style = "WPS"
- expiring_days = "30"
- communities = '["小区名称A","小区名称B","小区名称C","小区名称D","小区名称E","小区名称F","小区名称G","小区名称H"]'
- house_tags = '["楼层低","有电梯","近地铁","有家具","有空调","有车位","精装修","民水民电","随时看房"]'

## 三、后端 API 接口

### 房源
GET /api/houses?status=&area_min=&area_max=&tags=&room=&hall=
  返回数组，每条包含房源表所有字段；筛选逻辑：status 精确匹配；area_min/area_max 数值范围；tags 任意一个匹配；room/hall 精确匹配。
POST /api/houses   body 含所有字段（除 id）
PUT /api/houses/<id>
DELETE /api/houses/<id>

### 客户
GET /api/customers?status=   status 可选 跟进中/已签单/已放弃，返回数组。
POST /api/customers
PUT /api/customers/<id>
DELETE /api/customers/<id>

### 合同
GET /api/contracts   无筛选，返回数组。
POST /api/contracts   body: sign_date, contract_code, house_code, customer_code, months, start_date, end_date, deposit。自动计算 total_amount，自动更新房源状态。
DELETE /api/contracts/<id>  对应房源状态改回空闲。
辅助接口：
GET /api/houses/by_code/<house_code>   返回房源详情
GET /api/customers/by_code/<customer_code>  返回客户详情

### 数据看板
GET /api/dashboard/summary -> { total_houses, month_amount, month_count, total_customers }
GET /api/dashboard/amount_trend -> [{ date, amount }] 最近15天
GET /api/dashboard/customer_trend -> [{ month, count }] 最近7个月
GET /api/dashboard/house_status -> { vacant, expiring, rented, rate }
GET /api/dashboard/top_communities -> [{ community, count }] top5
GET /api/dashboard/best_day -> { date, amount }
GET /api/dashboard/best_month_customers -> { month, count }

### 参数设置
GET /api/settings  返回所有 key-value
PUT /api/settings   body 包含要修改的 key-value
POST /api/settings/reset   清空房源、客户、合同表，恢复 settings 默认值

### 【新增】示例数据管理
POST /api/import-example   清空房源、客户、合同表，从打包的 Excel 文件导入示例数据（格式转换见后）。返回成功/失败。
POST /api/delete-test-data  清空房源、客户、合同表，保留 settings。返回成功/失败。

## 四、前端界面与交互

### 4.1 整体布局
- 左侧菜单：房源管理、客户管理、交易流水、统计看板、参数设置
- 右侧内容区

### 4.2 房源管理页面

**视图**：卡片视图（默认）和表格视图可切换。

**卡片视图特性**：
- 按小区名称分组显示。每个分组标题为该小区名称，下方为该小区的房源卡片网格。
- 分组标题右侧有“+”/“-”图标可单独展开/收起该分组。
- 页面顶部提供三个独立按钮：
  - **“全部折叠”**：收起所有分组，只显示小区名称（可带“+”号），按钮文字变为 **“全部展开”**。
  - **“全部展开”**：展开所有分组，显示每个小区下的所有房源卡片，按钮文字变为 **“全部折叠”**。
  - **“全部房源”**：触发异步加载过程。
    - 显示进度指示器，格式：“当前进度：X --- Y”，进度条百分比显示。
    - X 递增直到等于总房源数 Y，弹出弹窗“加载完成”。
    - 关闭后自动切换为“全部展开”状态。

**高级筛选**：模态框支持状态、面积范围、标签（多选）、室、厅。确认后刷新列表。

**添加/编辑房源**：表单含所有字段，小区名称和标签选项来自 settings。

**删除**：需二次确认。

### 4.3 客户管理页面
- 表格视图，显示所有字段。
- 顶部状态筛选按钮：全部、跟进中、已签单、已放弃。
- 添加/编辑/删除类似房源。

### 4.4 交易流水页面
- 表格显示所有合同字段，无筛选。
- 每行有“查看”按钮，跳转到“添加交易”页面并填充数据（可编辑保存）。
- “添加交易”按钮打开页面/模态框，包含合同信息、房源信息、客户信息三部分。房源编号/客户编号失焦自动带出详情。

### 4.5 统计看板页面
- 顶部四个指标卡片。
- 成交金额趋势折线图（15天）。
- 新增客户趋势柱状图（7个月）。
- 房源分布饼图及出租率。
- 小区排名表格（top5）。
- 最高成交日文本、最高新增客户月文本。

### 4.6 参数设置页面

页面分为上下两个白框（样式相同）：

**上半部分白框**（原有）：
- 列表卡片设置：卡片列数（数字输入），空闲/已租/即将到期样式（下拉或颜色选择器，WPS 映射为预设颜色）。
- 字段设置：小区名称列表（可增删改）、房源标签列表（可增删改）。
- 底部按钮：**“模板初始化”**（清空三张表 + 恢复 settings 默认值）。

**下半部分白框**（新增，位于上方白框下方）：
- 内部放置两个**并列**的按钮（样式与“模板初始化”相同）：
  1. **“导入示例数据”**：调用 POST /api/import-example，成功后提示“示例数据导入成功”。
  2. **“删除测试数据”**：调用 POST /api/delete-test-data，成功后提示“测试数据已删除”。

## 五、业务规则补充
- 编号自动递增规则：
  - 房源：FY + 5位数字，起始 FY00001。
  - 客户：F + 5位数字，起始 F00001。
  - 合同：FYH + 4位数字，起始 FYH0001。
- 每日或每次启动时，检查已租房源的到期日：若 expire_date <= 当前日期 + expiring_days，status 设为“即将到期”，否则为“已租”。
- 客户标签与房源标签共用 house_tags 列表。

## 六、示例数据导入格式转换（重要）
- Excel 文件：`房屋出租管理系统.xlsx`（需打包到 exe 同目录或嵌入）。
- 房源表：
  - 面积：去除“m²”后缀，转为浮点数。
  - 标签：将竖线“|”替换为逗号。
- 客户表：
  - 标签：竖线“|”替换为逗号。
- 合同表：
  - 押金为空时写入 NULL。
  - 合同金额重新计算：months * monthly_rent + deposit。
  - monthly_rent 使用合同表中的值，不与房源表强制一致。

## 九、实现提示（供参考，非强制）
- **看板状态计算**：在 `/api/dashboard/summary` 中，可根据房源表的 expire_date 和当前日期结合 settings 中的 expiring_days 动态计算 vacant/rented/expiring 数量。
- **前端分组**：使用 `Array.reduce()` 按 community 字段对房源数组分组，再用 `v-for` 渲染分组和卡片。
- **动态样式**：根据 settings 中的 `vacant_style` 等值，为不同状态的卡片绑定不同的 CSS 类（例如 `.vacant-card` 背景绿色等）。
- **身份证处理**：本规格书不要求加密存储，但前端显示时可做简单脱敏（如 `230211********3215`）以提升观感，存储仍为明文。
- **操作日志**：本规格书不要求记录操作日志，如有需要可后续扩展。
