# 出租屋管理系统 — 开发文档（维护手册）

> 需求规格见《开发规范.md》。本文档面向维护者：架构、环境、流程、经验与已知事项。

## 一、架构

- PyWebView 桌面壳 + Flask 后端 + Vue3/Element Plus/ECharts 前端 + SQLite
- **开发模式**：`启动脚本.py` 起 Flask（端口 5000）+ pywebview 窗口；数据库 `backend/data/house_rent.db`
- **打包模式**：`build\build.py` → PyInstaller（`build\build.spec`）→ `build/dist/房屋出租管理系统.exe`；数据库在 `%APPDATA%/房屋出租管理系统/`
- 前端构建产物 `frontend/dist` 由 Flask 托管（git 忽略）
- 后端全中文变量约定：构建后 chunk 中函数名混淆为拼音，正常现象
- 后端路由按资源分模块：houses / customers / contracts / dashboard / settings（`backend/routes/`）

## 二、开发环境

- 包管理：uv（`.venv` 虚拟环境）
- uv 缓存位于自定义路径（沙箱外）；受限环境下可用 `UV_CACHE_DIR` 指向 Temp 临时目录执行 `uv lock` / `uv sync`
- PowerShell 环境：注意 UTF-8 编码；git 多行提交消息用多个 `-m`（无 heredoc）
- 运行 Python 一律 `.venv\Scripts\python.exe 完整路径`，不 cd 切换

## 三、测试与质量

- 测试：`pytest backend/tests`（23 个用例），覆盖合同校验、状态联动、看板统计等
- Lint：`ruff check backend`
- 新增校验/业务逻辑必须带测试；修复前先跑全量确认基线绿
- 造测试数据：`backend/generate_data.py`（100 房源/30 客户/35 合同，跑完删除 `backend/data/house_rent.db` 即恢复空库）

## 四、打包流程

- `build\build.py`：对比前端源码（src/public + package.json/vite.config.js）与 dist 的 mtime，源码有更新才重建前端，之后 PyInstaller 打包
- 产物：`build/dist/房屋出租管理系统.exe`（中间文件在 `build/work/`，均被 gitignore）
- 打包链四件套：`build/build.py` + `build/build.spec` + `启动脚本.py`（根目录）+ `build/icon.ico`，互相引用，勿单独挪动或改名
- 依赖变动后记得先 `uv lock` 再打包

## 五、Git 与协作

- 本地 git，无远程备份
- 每轮改动自测通过即提交；大改动（新功能/重写）前先提交现状当存档点
- 问题处理规则（详见 `.trae/rules/project_rules.md`）：
  - A 类（纯文本 + 零行为变化）：立即修，顺手提交
  - B 类（有行为影响）：集中清单 → 任务收尾统一呈现 → 用户拍板 → 一批改 + 全量回归 + 单次提交
  - 收工时集中清单必须清零

## 六、UI 自动化验证经验（TRAE-browseruse）

- 子代理转述的网络证据会被它自身行为污染（代理会自行 navigate API URL 抓包）→ 关键调试用主对话 Skill `TRAE-browseruse` 亲自操作
- `browser_fill` 原子设值不派发 input 事件 → Vue v-model 不同步，提交数据为空；用 `browser_type` slowly=true 逐字符输入才同步
- 自动化点击不产生原生 focus/blur 事件链 → Element Plus `@blur` 永不触发（真实用户不受影响）；验证依赖 blur 的功能需注入 document 原生事件监听取证
- `el-date-picker` 可直接输入完整日期 + Enter 确认
- 验证写操作前先备份数据库到 Temp；测完用 API 清理自建测试数据
